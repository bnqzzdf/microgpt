# 基础课程重设计：从字符编号到看懂一次预测

日期：2026-10-17。状态：已按本方案实施五阶段 21 小节；用户试学验收待进行。保留当前「课程学习 / 自由实验」两级导航。

## 1. 问题与目标

现有第一关能帮助用户理解字符与 Token ID，但第二关同时引入 embedding、16 维状态、Attention、MLP、logits 和 Softmax。页面直接展示概率，没有让初学者看到一个候选的分数如何计算。第三关注意力又默认用户理解向量、点积、加权混合、Q/K/V 和多头。只改导航或增加术语表无法解决这些知识断层。

目标读者无需机器学习、线性代数或微积分背景；能看懂普通加减乘除。遇到负数乘法、平方、开方和百分比时提供就地小例子，不要求读者先跳去学习数学课程。

主要验收目标：用户能沿着页面回答「输入的数字在哪里、哪些是固定参数、每一步如何算、候选分数怎样产生、怎样变成概率」。训练与生成建立在这条可追踪的计算链上。

## 2. 教学规则

- 一个短小节只负责一个主要理解目标；复杂模块可以连续占多个小节。
- 顺序为具体问题、观察/操作、逐步计算、用自己的话解释、最后命名术语。术语首次出现时同时显示熟悉说法，例如「一排数字（向量）」。
- 不用「学习到语义」「提取特征」替代具体运算，也不为向量每一格虚构可解释含义。
- 详细体现在计算可展开、数字来源可追溯和例子连续，而不是正文更长。
- 主线回答必需问题；公式推导、矩阵记号、源码和优化算法细节按需展开。
- 课程序号只表示推荐顺序。用户随时可跳转、跳过理解题、打开实验或返回补基础，不设答题锁。
- 先说明「这里的数字来自已经训练好的表，如何得到它们将在训练阶段解释」，不提前塞入梯度和优化器。
- 教学顺序可以不同于程序执行顺序；完整前向计算页必须按当前实现的实际顺序展示，不能把教学顺序画成计算链。

## 3. 课程结构

初稿为五个阶段、21 个短小节。数量是设计结果，不作为产品限制。试学后可进一步拆分；不继续承诺原来的「六关、15–20 分钟」。完成时间应在实际试学后估计。

| 阶段 / 小节 | 学习者的问题 | 核心交互与过关证据 |
| --- | --- | --- |
| A1 字符与编号 | 模型怎样区分字符？ | 保留编码实验；能指出当前字符、ID 和下一个字符目标 |
| A2 编号只是地址 | ID 越大是否代表越重要？ | 重排教学表的行地址，同时一致更新映射，表示不变；区分地址和数值大小 |
| A3 一排数字 | 向量和维度是什么？ | 从 1 个数到 3 个数，数格子；知道三维在这里指 3 个分量，不要求空间坐标知识 |
| A4 查表得到表示 | embedding 从哪里来？ | 点击字符→定位行→取出 3 个数；知道这是一张参数表、不是由 ID 数值自动推算出来 |
| B1 给一个候选打分 | 一排数怎样变成一个分数？ | 逐项相乘、累计求和；区分当前输入数值与候选的评分权重 |
| B2 给多个候选打分 | 为什么每个候选都有一个 logit？ | 同一排输入换用各候选的一行权重，得到多个分数；此时才引入 logit 和点积术语 |
| B3 分数变成概率 | 为什么分数还不是概率？ | 观察正负分数，经指数变成正数，再除以总和；能解释分母包含所有候选 |
| B4 对照真实规模 | 16 维、27 个候选有什么变化？ | 3 格/3 候选与 16 格/27 候选并排；使用真实最终状态核对一个字母的 16 项求和，标明该状态的生成将在 C 阶段拆解 |
| C1 加入位置 | 两个相同字母怎样区分先后？ | 展示字符表、位置表及逐项相加；分开 Token ID 和位置 ID |
| C2 从前文读取信息 | 如何把前面几个位置的信息混在一起？ | 先用给定的非负权重做加权平均；明确权重暂由教学示例指定，未解释真实权重来源 |
| C3 决定读取多少 | 注意力权重怎样算出？ | 用已学过的线性计算得到 Q/K，算匹配分数、缩放、遮挡未来、Softmax；先单头、少量位置 |
| C4 读取什么内容 | Value 与 Key 的作用有什么不同？ | 追踪 V 的投影与加权求和，再展开本模型 4 个头、每头 4 个数和输出投影；不赋予各头未经证实的语义 |
| C5 调整数值尺度 | RMSNorm 实际做了什么？ | 平方→求平均→开方→统一相除，说明小常数作用；观察相对比例，不把结果叫概率 |
| C6 进一步加工状态 | MLP 做了什么？ | 沿用乘加计算，展示 16→64→16，单独演示负数经过 ReLU 变为 0；展开后再展示矩阵全貌 |
| C7 保留原有信息 | 残差连接为什么是相加？ | 显示输入分支、加工分支及逐项相加；不把残差当成前后顺序的两次状态更新 |
| C8 走完一次真实预测 | 从 e 到 m 的分数能否全部追踪？ | 按真实执行顺序串联上述模块；点击一个 logit 追踪到 16 项乘积、最终状态和此前计算 |
| D1 衡量一次预测 | 给正确字符多少概率，算好还是差？ | 先比较正确目标概率，再计算 −ln(p) 与各位置平均；单独解释 ln，不用最高概率是否猜对代替 Loss |
| D2 参数怎样影响错误 | 改一个数，损失会怎样？ | 对同一参数做微小正负扰动，在同一状态上比较；建立梯度的变化率含义，再展示真实反向传播与分支累积 |
| D3 从梯度到更新 | 学习到底改了什么？ | 标出参数更新前后与新损失，先解释沿梯度反方向的小步调整，再介绍实际使用 Adam；单次 Loss 不保证下降 |
| E1 把预测接成生成 | 一个字符怎样变成完整名字？ | 预测→抽取→送回输入，真实历史与自己生成的历史并列；参数不因普通生成而更新 |
| E2 控制采样并回顾 | 温度为什么影响输出？ | 比较完整分布、采样随机数与停止条件；回顾后进入现有「从模型到助手」进阶篇 |

阶段 A/B 的简化评分不包含上下文，不能暗示查 embedding 后直接评分就是完整 GPT。C2 先学习混合运算，C3 再解释权重来源；C3 使用的输入注明是已做尺度调整的状态，具体调整在 C5 展开。C8 消除这些暂时省略的环节。

## 4. 两套示例及过渡

### 4.1 可手算的教学示例

采用一张人为指定的 3 维查表和 3 个候选 a、b、c。页面持续显示「教学示例：3 个数、3 个候选；参数人为设置，未训练，不代表真实模型输出」。固定同一个例子跨 A/B 使用，只有用户主动调整时才变化。

示例当前表示 x = [1, 2, −1]：

| 候选 | 评分权重 | 逐项乘积 | 原始分数 |
| --- | --- | --- | --- |
| a | [1, 0, 1] | [1, 0, −1] | 0 |
| b | [0, 1, 0] | [0, 2, 0] | 2 |
| c | [−1, 0, 1] | [−1, 0, −1] | −2 |

Softmax 的对应概率约为 11.73%、86.68%、1.59%。先逐项展示乘加，再命名点积；先展示多个分数，再命名 logits。切换候选时输入表示保持不变，只有所选权重行变化。输入和参数用文字标签区分，同时提供颜色辅助。

允许调整一个权重并观察结果，但始终标注「手动调整」，不可把手动操作描述为模型自动学习。早期不增加第三套模型或随机参数，避免对照对象过多。

### 4.2 真实模型

沿用预训练名字模型、固定前缀 <BOS>, e 和真实计算 trace。标明「真实模型：16 个数、27 个候选」，候选包含 a–z 和兼作开始/结束的 <BOS>。真实 embedding 表和输出评分表都是 27×16，但属于不同参数表，不共享或混称。

B4 先拿到真实最终状态，练习已学会的评分运算；用清楚的占位说明「这 16 个数已结合位置和前文，下一阶段逐步拆开」，禁止用一串未解释的术语作为解释。

C8 必须按 js/model.js 实际前向顺序展示：字符表+位置表→RMSNorm→注意力前 RMSNorm→Q/K/V 与因果多头注意力→输出投影+残差→MLP 前 RMSNorm→线性/ReLU/线性+残差→输出评分表→Softmax。不为迎合常见架构图新增项目中不存在的末尾归一化。

概率计算使用全部 27 个候选。可折叠低概率候选，但不能只对展示的前几名重新归一化。显示经过取整的数时，说明最终值来自未取整数值。

## 5. 页面设计

课程二级导航仍为「基础篇 / 进阶篇」。根据实际试用反馈，基础篇目录采用紧凑的「阶段 / 小节」选择栏，取消五列目录及内部滚动。选择栏在实验页顶部保持可用，附带上一节/下一节；切换后当前标题定位在导航下方。课程介绍与学习记录默认折叠。每节显示当前位置、目标和下一节的问题。

每节固定使用以下顺序：

1. 一句具体问题，以及已经知道的前提；缺少前提时提供返回相关小节的入口。
2. 本节例子的输入，清晰标记教学示例或真实模型。
3. 一个主要操作，例如「取出这一行」「计算下一项」「比较候选」。
4. 输入、参数、当前运算和输出相邻展示；新出现的数字可点开查看来源。
5. 一道检查概念的题，答错反馈指向对应运算步骤。只打开页面或点击按钮不自动标记掌握。
6. 一句可以带走的结论，以及下一节将解决的问题。

右侧源码栏改为默认折叠的「查看公式与实际代码」，不让零基础用户同时处理模型、公式和程序三种表示。早期页头隐藏模型规模详情，B4 起可展开查看。术语解释仍在当前位置可获取，不能要求用户频繁滚动到页底。

在 A/B 阶段进入自由实验时，显示「这是完整模型实验；尚未学习的部分稍后解释」，保留返回原小节入口。也提供本节对应操作的聚焦入口，不自动转走或丢失实验结果。

## 6. 学习进度与现有内容迁移

- 基础课保留同一入口；原六关重组到新阶段，不另留一个同级的旧版课程让新用户选择。
- 原 Token 内容迁移至 A1；预测分布至 B3/B4；注意力至 C3/C4；Loss 至 D1；训练至 D2/D3；生成至 E1/E2。已有源码、模型和可视化尽量复用。
- 六关编号不能继续作为业务逻辑。用稳定的小节 ID、阶段 ID 和独立实验类型组织课程，替换 index===1 等渲染和运行分支以及写死的 /6。
- 新进度使用版本化结构：当前小节 ID、访问记录、理解检查状态。旧课程记录只映射到相关新小节作为继续位置或旧版学习记录；题目与目标改变时不继承「已掌握」。不修改进阶篇自己的进度。
- 清楚说明课程升级后新增了基础内容，可从头学习或回到建议位置；不静默清空用户原记录。权重和运行轨迹继续不跨刷新保存。
- 课程、教学示例、自由实验、进阶真实推断保持状态隔离。新小节的重置不能重置别处权重或随机数。
- 中英切换只改文案，保持步骤、数值和实验状态。基础篇完成后的进阶入口保留，进阶文案中原来「六关」的称呼同步更新。

## 7. 实施顺序与交付范围

第一批：先完成 A1–B3 的连贯学习原型，尤其查表→向量→乘加→多个分数→概率。这是本次反馈暴露的首要断点。将基础课框架改成阶段/稳定小节 ID，但不发布含空章节的导航。

第二批：完成 B4–C8 的真实模型过渡，补充必要 trace 与追踪视图；数值必须来自实际前向计算，不能复制静态文字冒充运行结果。

第三批：重组 D/E，完成进度迁移、进阶衔接、双语和自由实验往返。内部可分批验证，对外切换时主线必须连贯，不能将新基础与旧第二关直接拼接后宣称重设计完成。

本次改版不改模型规模、不引入远程模型服务、不改部署方式。五阶段主线已在本地实现；下方教学验收仍需实际试学。

## 8. 验收

### 教学验收

先请提出当前困难的用户试学 A/B，再根据反馈修订。主要观察不依赖用户背出术语：

- 能指出 ID 是地址，并从表中取对一行。
- 能解释「16 维」意味着 16 个分量，而不是 16 个 token。
- 能手算示例中的一个候选分数，指出输入和权重的区别。
- 能解释为什么同一输入会得到多个不同分数。
- 能解释候选概率要与所有候选分数一起计算。
- 能区分简化评分与完整 GPT，并知道真实状态还包含上下文处理。
- 到 C8 时，能从一个真实 logit 沿页面找到乘积项、最终状态及其来路。

若读者需要自行搜索一个新术语才能继续，视为该节尚需补充或拆分。若只能复述名称、不能指出数字来源，不视为已理解。实际试学结果单独记录，不以自动化测试代替。
