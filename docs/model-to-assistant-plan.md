# 从模型到助手：下一阶段教学改进方案

状态：待评审，尚未实现。日期：2026-10-17。现状核对基线：`3900f25`。

方案起草：Astra（high）；本次交付仅为方案文档，未实施功能。

后续实施更新（2026-10-17）：离线进阶篇代码与自动化检查已落地，实际读者与辅助技术等发布验收尚未全部完成。具体范围及限制见[实施记录](bridge-implementation.md)。上文“未实施”为方案初稿交付时的状态。

## 0. 先做什么：决策摘要

建议保留现有六关和四个沙盒，另加一个约 15–20 分钟的可选桥接篇「从模型到助手」。目标不是把名字模型包装成聊天机器人，而是解释：聊天如何成为模型输入、一次生成如何执行、语言与解题能力从哪里来，以及怎样验证答案。

默认首个可交付 MVP 是**无需密钥、不调用外部模型的离线桥接篇**，含三个模块与一张必读的能力来源卡：

1. **拆开一段对话**：可操作的消息 → 教学模板 → 教学 token；删除历史并查看本次输入里还剩什么。所有变换真实执行，但教学 token 不冒充任何真实聊天模型的 token。
2. **走完一次生成**：复用现有名字模型，在独立实例上实际运行前缀处理、KV cache 与逐 token 生成；明确权重未变，流式显示不是“正在思考”的证据。
3. **检查一次解题**：人工编写的直接答案/分步解答，配实际运行的确定性判题器；先学检查证据，不从案例推导模型能力提升。
4. 在第三模块前用短卡连接预训练、指令示范、偏好或可验证奖励与固定权重下的生成；不在浏览器训练大语言模型。

真实语言模型实验放在第二阶段：保留最小可插拔接口，但只有部署者明确选择模型、运行位置、数据政策与预算后才启用。它补齐“实际模型是否因历史或求解策略而改变表现”的经验验证；MVP 不声称已经完成这项验证。

取舍理由：直接追加“聊天、推理”动画容易把新增文本误认成现有 4,192 参数模型的能力；先建立输入、计算、能力、证据四条边界，教学收益更明确，也能延续静态部署与中英双语体验。首版不做模型排行榜、RAG、工具调用、agent、长期记忆系统或开放聊天产品。

评审只需先确认：是否接受上述离线 MVP；若坚持首版必须看到真实语言模型回答，则按第 11 节先决定运行位置与数据授权，工期和部署范围相应扩大。中英实时切换、无障碍和真实性标记是既定要求，不是选配。

## 2. 教学目标、非目标与概念边界

### 2.1 可检查的学习目标

完成后，学习者应能：

- 在聊天气泡、角色字段、模板标记、token 序列之间指出对应关系，并说明它们不等同。
- 说明聊天界面显示了什么，不代表本次模型实际接收了什么；能检查历史是否进入本次上下文。
- 区分消息历史、上下文窗口、KV cache、持久记忆与训练权重。
- 按顺序解释权重加载、prefill、decode、停止与 UI 更新，并指出哪些操作改变权重。
- 解释为什么给名字模型加 `assistant` 标签不会让它学会中文问答。
- 把 inference 译为“模型推断/生成执行”，把 reasoning 译为“推理解题”；知道后者是需评估的能力，而不是前者的另一套必经程序。
- 对“分步写得更长所以更正确”的说法要求答案核验与对照实验；不把公开解释认作完整内部思维过程。

### 2.2 五类“记住”必须分开

| 对象 | 本篇的准确定义 | 改变它会怎样 | 不应教成 |
| --- | --- | --- | --- |
| 消息历史 | 应用持有的角色/内容记录，可多于本次发送内容 | 改变可供组装输入的材料；是否发送由应用决定 | 聊天框里有就必然被模型读取 |
| 本次上下文 / 上下文窗口 | 本次实际提供的 token 前缀，以及模型/运行配置允许处理的长度限制 | 选择、删减历史会改变本次输入；生成也消耗可用长度预算 | 永久记忆；越接近长度上限仍保证准确利用所有信息 |
| KV cache | 固定模型处理某一有效前缀时得到的逐层 Key/Value 中间结果 | 在有效条件下复用可避免重复计算；前缀或权重变了就要失效/重建 | 新学到的知识；额外扩大上下文窗口的硬盘 |
| 持久记忆 | 应用在请求外保存、之后选择检索或注入的资料 | 只有被重新提供等机制使用时，才可能影响当前回答 | 模型天然记住所有历史；等于权重更新 |
| 训练权重 | 学习获得的参数；本篇普通生成期间固定 | 训练/微调的优化步骤会更新参数；替换检查点也会换参数 | 每发送一句话就自动反向传播 |

KV 的官方解释是复用过去 token 的 K/V 计算，不是保存对话含义的独立数据库；参见 [Hugging Face：How caching works](https://huggingface.co/docs/transformers/cache_explanation)。本篇采用简单完整前缀缓存模型；滑窗、跨请求前缀共享等优化仅在扩展说明出现。清空 KV 但用同样输入重新计算，与从输入中删掉历史，是两个不同实验。产品可能在服务端管理会话，本篇描述的是最终到达模型的上下文，不强行要求每次 HTTP 请求都携带完整历史。

### 2.3 能力来源不是模板魔法

必读卡控制在三步，每一步提供“数据/优化目标/是否改权重”三个字段：

1. **预训练**：从大量文本中的续写任务学习统计规律与可迁移能力；本仓库只在名字数据上学习，数据、词表与规模都不同。
2. **后训练**：示范答案可用于监督微调；偏好比较或可验证结果可提供进一步训练信号。以 InstructGPT 的 SFT → 奖励模型 → PPO 为一个具体历史案例，不宣称所有模型都走同一流程。参见 [InstructGPT 原论文，§3.1](https://arxiv.org/html/2203.02155v1#S3.SS1)。
3. **使用时生成**：把输入和已生成内容放进上下文，执行固定权重的计算；提示改变的是当前条件，不等于在做上述训练。

补充一张可展开案例卡：DeepSeek-R1-Zero 研究了在已有基础模型上通过强化学习与可验证奖励培养解题行为；R1 则加入冷启动数据和多阶段训练。这支持“训练方式会影响求解行为”的教学连接，不支持“给任意模型写 `<think>` 就能复现能力”。参见 [DeepSeek-R1 原论文，§2.2–2.3](https://arxiv.org/html/2501.12948v1)。不搬用论文分数为本项目作能力保证，也不实现其训练流水线。

### 2.4 非目标

首版不训练中文聊天模型、不实现 RLHF/GRPO、不提供开放问答承诺；不展示或声称读取隐藏思维链；不制作“注意力亮在哪里就是思考到哪里”的解释。RAG/工具/agent 留作后续系统层扩展：只有学会区分模型输入、模型输出和外部执行后，再分别讲检索注入、工具结果与循环控制；不把它们定义成所有 reasoning 的必要条件。

## 3. 学习路径与信息架构

建议入口为第六关回顾后的「继续：从模型到助手」，同时允许从主导航直接进入。仍可随时返回六关或沙盒，不增加答题解锁。初次直达时提供一张 60 秒前置回顾：token → 条件概率 → 自回归；需要时链接原第 1、3、5、6 关。

依赖顺序如下：

```text
原六关：token / 因果注意力 / 训练与生成
  → A 对话如何组成输入：消息、模板、教学 token、历史选择
  → B 一次生成怎样执行：固定权重、prefill、KV、decode、停止
  → 能力来源卡：预训练与后训练（连接原第 5 关）
  → C 解题怎样验证：直接答案/公开分步解答、判题、成本与实验边界
  → 可选真实模式：在相同观测框架中接入实际语言模型
```

导航使用稳定模块 ID（`conversation`、`execution`、`verification`），与原六关数字索引隔离。每模块采用“先预测 → 改一个条件 → 看证据 → 理解检查”；一个主操作面板即可，不同时铺开所有内部细节。

## 4. 模块规格：交互、数据、检查题

### A. 拆开一段对话

**默认样例**：用户“本轮口令是青柠 47。”、助手“收到。”、用户“刚才的口令是什么？”；英文另有固定内容版本。声明这是人工编写的教材，不是模型生成记录。

界面四层逐层展开：聊天气泡 → `{role, content}` 消息表 → 序列化文本 → 教学 token 表。每层显示“来源”和“下一步如何使用”。点击角色或内容，高亮对应片段；选择“显示/隐藏历史”时，聊天气泡保持在屏幕上，被排除消息标记“未进入本次输入”，对比本次序列差异。

MVP 的 `teaching-chat-v1` 模板使用保留标记明确边界；教学 tokenizer 使用固定保留 ID 加 Unicode 码点的确定性映射，显示“教学 tokenizer；不是现有名字词表，也不是某个真实聊天模型”。其 token 数仅用于教学预算，不标成 API 计费或真实模型长度。普通内容中的保留标记必须转义/拒绝为结构标记，避免把输入文字误作角色。该 tokenizer 不参与概率计算，不给 token 配假 logits、attention 或概率。

真实聊天模型应使用其匹配的模板与 tokenizer，格式并不通用；角色标记、结束标记和生成提示也不必是同一种东西。此连接依据 [Hugging Face：Chat templates](https://huggingface.co/docs/transformers/chat_templating)。后续真实适配器不能复用 `teaching-chat-v1` 冒充目标格式。

**历史实验不伪装模型回答**：旁边运行确定性“输入证据检查器”，只回答“本次输入是否含口令定义？来自哪条消息？”。移除定义后显示“本次输入无此证据”，不自动播放一条冒充 LLM 的“我忘记了”。UI 明示：这是可见性检查，不证明有历史一定答对、无历史一定答错。第二阶段才实际比较模型回答。

增加一个教学上下文预算开关，按完整消息选取并显示排除理由；默认超限阻止继续，由学习者明确选择移除旧轮次，不静默截断，不切掉半个角色标记。系统说明、当前问题和生成提示若仍超限则报错。教学预算与名字模型的 16 位置预算分开标注。

理解检查：

- “聊天框保留口令消息，但本次输入未包含它；模型一定还能用它吗？”正确：不能据聊天界面判断，要看实际上下文；也不排除猜中。
- “把角色改成 assistant 是否更新了训练权重？”正确：没有，只改输入结构。
- “教学 token ID 可以直接送入现有名字模型吗？”正确：不可以，词表和用途不同。

### B. 走完一次真实生成

本模块明确切换对象：“下面回到本地名字模型，实际计算可检查；它不接收上一模块的聊天内容。”默认名字前缀 `em`，可选空前缀和 `ann`；MVP 不接受任意字符。使用新的独立模型实例和缓存，不复用课程或沙盒正在训练的实例。

状态机及用户可见证据：

| 阶段 | 实际动作 | 展示证据 / 不可混淆处 |
| --- | --- | --- |
| 加载权重 | 从已随页面加载的 `MICROGPT_WEIGHTS` 建立独立实例 | 检查点标识、参数数；这不是下载大模型，也不为每个 token 再加载 |
| 准备输入 | 检查前缀；以 `tokenizer.encode(prefix).slice(0, -1)` 得到 BOS + 前缀 | 展示真实 ID；训练样本的末尾 BOS 不能提前结束提示 |
| Prefill / 处理提示前缀 | 顺序调用现有 `forward`，建立完整前缀 KV | 每层已缓存位置数、最后位置 logits；不是产生回答前先训练一次 |
| 首个输出与 Decode | 由 prefill 最后 logits 抽出首 token；之后把刚生成 token 送入 `forward` 再抽样 | 当前输入、输出 token、位置和采样随机数；不要把首个 token 错画为另一次完整 prefill |
| 停止 | BOS、长度预算、用户取消或错误 | 显示具体原因；达到预算不等于模型完成了答案 |
| 显示更新 | UI 按事件更新文本；可切单步/自动 | 暂停显示、停止计算分开；延时播放不算模型耗时 |

本仓库用逐位置处理表达 prefill，方便观察；真实运行库可以并行/分块处理前缀，不能拿这个标量实现的速度推断大模型性能。现有 KV 数组和前向路径是直接证据，概念参见 [HF KV cache 说明](https://huggingface.co/docs/transformers/cache_explanation)。流式传输是逐步交付输出的 UI/传输选择，并非另一个学习过程；参见 [HF TGI：Streaming](https://huggingface.co/docs/text-generation-inference/en/conceptual/streaming)。

两项操作即可支撑核心概念：

1. **清缓存并重算同一前缀**：逐项比较下一 token 概率，容差内应一致；展示真实 `forward` 调用计数，不承诺墙钟加速比。不做“清缓存后模型忘记口令”的假演示。
2. **改变前缀再运行**：新建缓存并恢复同一种子，显示输入已改变，权重未变。不同前缀不保证不同最终样本，所以先比较分布，再观察输出。

预算使用显式保守规则 `promptTokenCount + maxNewTokens <= blockSize`，`promptTokenCount` 包含 BOS；宁可留出一个位置余量，不越界访问位置嵌入。该规则是本实验的限制，不宣称是所有推理引擎的精确计数方式。停止在 BOS 时不再把 BOS 送入下一次前向。每次运行前后核对参数快照；不能只靠一个“权重固定”的图标证明。

理解检查：“清空 KV 后重算相同输入需要重新训练吗？”“正在逐字显示是否表示权重仍在学习？”“新输出来自提示的最后分布，还是必须先拿到正确答案？”答案分别为不需要、不表示、来自当前前缀的下一 token 分布。

### C. 检查一次解题，而不是观看“思考动画”

先读能力来源卡，再进入同题对照。MVP 仅使用人工编写的四组教材：直接和分步都正确；直接错误而分步正确；分步过程有错误；答案正确但解释与条件不一致。比如 `18 × 7` 的答案是 `126`，错误分步“`20 × 7 − 2 = 138`”可定位到少减了 `2 × 7`；所有值由测试核对。

交互顺序：隐藏判定，学习者先选可信答案 → 展开公开解答文本 → 点击“按规则验算” → 展示最终答案核对与支持的步骤检查 → 切换另一题。判题器为普通程序，明确标记“确定性验证，不是语言模型”。首版支持整数算术和有限步骤状态更新，不执行输入中的 JavaScript，不用 `eval`，不引入 LLM 裁判。

只显示实际可得的成本：教材字符数、已列出的验算步骤数；不显示虚构 token 消耗、耗时、价格或成功率。长短对照服务于“文字越多不等于证据越强”，不是假装完成模型性能实验。人工案例不能证明真实模型 reasoning 提升，也不能用四组挑选案例统计“分步提升 X%”。

公开分步解答是可审查文本，不是全部内部状态。相关研究发现模型解释可能遗漏影响答案的因素；因此本篇采用“公开解答/可观察输出”表述，参见 [Turpin 等：Unfaithful Explanations in Chain-of-Thought Prompting](https://arxiv.org/abs/2305.04388v2)。不要求真实服务暴露隐藏推理；服务若仅提供最终答案，依然可以评估最终正确性。

理解检查：“分步答案比直接答案长，能判定更正确吗？”“答案核验通过是否证明每一步都正确？”“人工对照案例能否证明某模型提升？”均为不能；反馈必须指向本次证据缺口，而不是只告诉学习者选错了。

## 5. 真实性标记与模式契约

标签位于每个结果面板标题旁，而不仅放在页脚；颜色之外同时显示文字，导出记录也保存同一分类。

| 来源标签 | 允许展示 | 禁止暗示 |
| --- | --- | --- |
| 教学结构 · 实际本地变换 | 教学消息、教学模板、教学 tokenizer 的确定性结果 | 这些 ID 就是某真实聊天模型的输入 |
| 本地真实模型计算 · 名字模型 | 真实 logits、概率、缓存与输出，标注模型/权重版本 | 中文对话或数学解题由名字模型完成 |
| 人工教材 · 非模型输出 | 人编回复与解答、实际判题结果 | 回放速度代表推理速度；案例代表模型成功率 |
| 真实模型记录回放 | 经来源清单核对的不可变历史请求/响应 | 当前在线结果；未经测量的内部状态 |
| 真实模型本次运行 | 明确配置的本地/远程模型输出及实际可见指标 | 未提供的 token、logprobs、KV、内部阶段或隐藏推理已被观测 |

未知数据统一用“未提供/不可观测”，不能填 0、动画估计值或名字模型概率。没有来源清单的文本只能作为人工/未知来源教材，不能标为真实记录。发生连接失败不能静默切成预设输出；如用户选择回放，必须更换来源标签和 run ID。

## 6. 技术与数据方案

### 6.1 状态与模块边界

维持普通 JavaScript 与静态资源，MVP 不增加构建系统。建议增加 `BridgeCourse` 负责导航和状态，纯函数集中于 `BridgeCore`；视图只消费记录，不因渲染或翻译重新采样。分开四块状态：

- `progress`：模块 ID、答题记录、回顾状态，独立保存于 `microgpt.bridge.v1`。
- `scenario`：消息、选中历史、模板/教学 tokenizer 版本、预算；仅内存。
- `run`：不可变运行配置与逐步事件，含模式、模型身份和停止原因；仅内存，显式导出。
- `presentation`：展开项、显示速度、焦点等；不影响模型结果。

刷新明确提示实验已重置；“重学桥接篇”只清自身进度与实验，不触碰原课程、自由沙盒或语言偏好。离开运行页面默认取消本篇自动推进并保留已有结果；返回不自动恢复外部请求。用 run ID 忽略取消后迟到的事件。

### 6.2 最小数据契约

以下为拟议接口，不是已经存在的代码：

```text
Scenario: id, version, contentLanguage, messages[], expectedEvidence?, task?
Message: id, role, content, included, exclusionReason?
Representation: kind(teaching|model), templateId, tokenizerId,
                revision, text, spans[], tokenIds?, tokenCount?, countSource
RunConfig: mode, scenarioId, modelIdentity, promptSnapshot,
           representation, decoding, requestedSeed, budget, protocolVersion
RunEvent: runId, sequence, type, timestamp, source,
          phase?, tokenId?, textDelta?, counts?, stopReason?, error?
RunResult: config, events, output, observableMetrics, verification,
           limitations[], provenance
```

`spans` 映射回消息/角色/内容，偏移约定统一为 JavaScript UTF-16 索引，tokenizer 的码点遍历显式转换偏移，测试中文与 emoji。`tokenIds` 和 token 数允许为空；“没有 token 边界的文本块”只能称为 chunk，不能给每块补造一个 token ID。

数据分三份：人工教材清单、确定性算术/状态任务、未来真实运行清单。每份都有版本、作者/来源、许可证或再分发确认、用途与校验和。真实数据记录模型仓库/服务 ID、不可变 revision（若提供）、tokenizer/template revision、权重量化/运行库版本（若可知）、输入、参数、原始输出和采集时间。拿不到字段应明确未知，不从模型展示名称猜版本。

### 6.3 可插拔但默认关闭的真实模型接口

MVP 定义并测试接口，不实现通用 API 平台；第二阶段仅接入一种经批准的后端。

```text
adapter.describe() → identity, locality, capabilities, limits, privacyNotice
adapter.prepare(messages, options) → requestPreview,
                                    representation(exact|opaque), budgetCheck
adapter.run(prepared, { signal }) → async events + final result
```

能力声明至少覆盖精确 tokenizer/模板可见性、token usage、seed、流式输出、阶段计时与取消支持。`prepare` 不发起推理；用户可检查实际发送内容。模板所有权必须唯一：要么适配器用配套 tokenizer 渲染，要么服务接受 messages 并在内部渲染。后者若不暴露模板，UI 显示“服务内部模板不可见”，不能把本地教学模板标成实际线上输入；也不能重复套模板或重复添加特殊 token。

本地模型选项由部署者明确配置运行服务/模型文件；下载体积、硬件要求、许可证与启动过程在实施选型时验证，不许承诺所有浏览器都能运行。远程 API 选项需要同源受控代理，密钥留在服务端，不进 HTML、仓库、localStorage 或导出记录。连接目标用部署配置白名单，不支持任意 URL 代理；限制输入、输出、并发和超时。

启用前显示发送目标、数据范围、是否可能留存、费用/配额政策，并取得明确确认；实际保留政策以选择的服务条款为准，不作“绝不留存”保证。默认只提供无个人信息教材；自定义内容须用户主动输入并确认发送。MVP 不扫描本地文件、不上传浏览历史、不请求密钥，也不发分析遥测。

### 6.4 推理事件不等于 UI 动画

内部本地 runner 可报告实际 load/prefill/decode 事件；远程模式通常只能可靠观测请求时间、首个可见块、后续块和完成，未披露阶段一律不虚构。取消优先中止底层请求；若只能停止接收，明确服务端可能仍继续计算/计费。超时、取消、截断、正常结束和服务错误分别保存；重试生成新的 run ID，不覆盖失败记录。

## 7. 双语、无障碍与窄屏

中英文接入遵循现有 `js/i18n.js`：每个标题、按钮、问题、选项、反馈、动态句子、错误和无障碍标签都同时登记。保留原文绑定和动态插值，模型数据插槽不递归翻译。`pre[data-source]` 只用于真实源码；原始消息、教学序列、真实 token、输出与记录使用 `data-no-i18n` 保护，周围解释和来源标签可翻译。

**界面语言与实验内容语言分开**：切 UI 语言只改变教学说明，不能翻译已有输入、改题、重跑模型或改变种子。人工教材另提供“载入中文/英文样例”，该按钮明确会开始一个新场景；中文与英文题库保留相同语义 ID，但分别记录输入快照，不当成相同 token 实验。首次载入可随 UI 语言选择教材，运行后固定内容。

新容器继承文档 `lang`，不要复制现有 `tab-course` 的固定 `zh-CN` 属性却漏掉更新。检查现有翻译器仅更新 `tab-course` 的逻辑（`js/i18n.js:417`），扩展时让新容器继承或统一更新；不要依赖当前并不存在的语言订阅 API。

交互必须支持键盘与可见焦点：消息使用勾选框，片段使用按钮，展开使用 `details`；不要求拖拽或仅悬停。表格有 caption/表头，来源不能只靠颜色，错误与状态用适当 live region。逐 token 显示默认不逐字打断屏幕阅读器，可按阶段/完成摘要播报；尊重减少动态效果偏好，提供立即显示和停止。默认不抢夺输入焦点。

在 390px 和 320px、两种 UI 语言与 200% 缩放下检查：多栏折成单列；长序列可换行，确需横向滚动的表格限制在标注容器内；页面不整体横向溢出。来源、停止原因和验证结果不能在窄屏隐藏。英文长标签与中文/emoji token 都要实测。

## 8. 可复现性与评估

### 8.1 三类评估分开报告

1. **实现正确性**：纯变换、模型不变性、缓存重算、预算、事件与 i18n 回归。
2. **学习效果**：模块前后同构但不完全重复的理解题，重点看“聊天=训练”“KV=长期记忆”“长解释=正确”的误解是否减少；完成率不等于理解。默认不收集数据，愿意参加的试用者可主动导出匿名答题记录。小规模试用只报告人数、题目和原始计数，不宣称普遍教育效应。
3. **模型表现**：仅第二阶段真实模式测量；人工教材不纳入。最终准确率与公开解释质量分别记录，不借某一项代替另一项。

### 8.2 离线可复现规则

教学变换和判题器：固定数据版本、模板和算法版本后精确相等。名字实验：固定权重文件校验和、前缀、温度、种子与算法版本；记录每次抽样随机数，重放比较 token 与容差内概率。不得把演示的等待时间计入模型耗时。跨 JavaScript 引擎的浮点细差可能在抽样边界影响轨迹；测试优先比较数值容差与明确边界用例，不许承诺跨所有硬件逐比特一致。

### 8.3 第二阶段最小对照协议

**历史条件实验**：同模型、同问题和解码参数，对比完整历史/移除关键历史；另有不依赖历史的控制题。使用不含隐私的随机口令，记录实际输入快照与种子支持情况。删历史后仍答对可能是猜测；有历史仍答错也是有效观测。MVP 的证据检查器只检查信息存在性，不替代这项实验。

**求解条件实验**：预先冻结 24 道程序生成的可验证题（12 道整数算术、12 道短状态更新），训练示例/教材与评估题分离。默认一轮每题两种条件各一次：A 要求仅给最终答案，B 要求给简短可核验步骤及最终答案；使用相同模型、任务文本、解码设置和每次相同输出上限，交错顺序，不只保留成功样本。上限作为实验配置记录；例如从 256 个输出 token 开始试跑，之后若修改须产生新协议版本，不能看完结果才为某个条件补预算。

若适配器支持随机采样和 seed，扩展为每条件 3 个预声明种子；若不支持，记录重复调用次数与 `seedSupported=false`，不伪造确定性。温度为 0/贪心也不承诺远程服务完全可复现。不同提示长度会改变计算负担与采样轨迹，相同种子并不意味着同一“随机思路”。模型若内部仍进行不可见推理，A/B 只能叫“输出指令条件”，不能叫“关闭/开启内部思考”。

判题器仅接受规定格式中的唯一最终答案；多答案、无法解析、预算截断各列原因，不能人工挑选其中正确片段。报告：

- 准确率：正确数/全部计划题次，并列完成数、服务失败数、未运行数；可另报已完成样本准确率，但必须展示分母。逐题展示 A/B 差异，不把基础设施故障解释为模型知识错误。
- 成本：真实可见的输入/输出 token、首个可见输出延迟、总延迟及停止原因。精确 token 不可得时单列字符数，不混算；隐藏 token 或服务计费量只用实际披露值。
- 解释检查：只验证判题器支持的算术等式或状态变更；其它文本注明未验证。最终答案正确不等于所有步骤真实、有效或忠实。
- 复现资料：题集版本、完整提示、模型/后端版本、运行时间、随机设置、量化与运行库（若已知）、所有原始输出、失败与限制。默认下载到本地，不上传。

24 题是便于复核的教学设计，不是可靠模型排行榜或能力认证。说明样本小、题型窄、可能有数据污染、语言和提示敏感性；不把较长输出与更好成绩解释为因果关系。只有模型和协议未变化才合并结果；中英结果分层展示。后续如加入多次采样、投票或验证后重试，要单列总 token/请求成本和选择规则，不混入单次 A/B。

| 新 `js/bridge-runner.js` | 独立名字模型 runner、事件协议、缓存重算与取消 | 复用 `GPT.forward`/`sampleFromProbs`；显式 RNG；不调用训练更新 |

| 第二阶段新 `js/bridge-adapters.js` 及选定部署目录 | 一种明确配置的真实后端 | API 代理不作为静态 MVP 的运行依赖 |
| 后续 `README.md` | 新入口、模式限制、配置与验证步骤 | 不宣称名字模型已变成聊天模型 |

MVP 必须通过的自动化验收：

- 教学消息在序列/片段映射中可追踪；移除历史不改气泡存档；未知角色、空内容、保留标记、中文与 emoji 有确定行为；超限不默默截断。
- 不将聊天输入传给名字 `Tokenizer` 或 `GPT`；教学 token 与真实 token 类型/来源不混用；人编案例不附模型概率。
- 空前缀/`em`/`ann` 的 prompt token 正确且无末尾 BOS；prefill/首 token/decode 顺序正确；每次前向位置均小于 `blockSize`。
- 固定种子重置后可复核；清缓存重算同前缀的分布容差内一致；变更前缀、模型或配置使旧缓存失效；运行前后权重不变；旧课程与沙盒实例不变。
- BOS、预算、取消、错误分别结束；取消后迟到事件不污染新 run；语言切换和视图展开不消耗随机数、不新增前向调用。
- 判题器对全部预设正确/错误案例与边界输入给出预期结果；没有动态执行任意字符串；教材与评估数据分离。
- 每个输出都有来源；字段不可观测时为空并提示；导出记录保留版本和限制、排除凭据；不把回放计时记为推理时长。
- 桥接篇进度损坏/存储禁用时仍可使用；重置不影响原课程；刷新不恢复消息和模型输出。
- 现有 `node tests/model-checks.cjs`、`node tests/i18n-checks.cjs` 以及新 `node tests/bridge-checks.cjs` 均通过；新 i18n 覆盖三模块所有题目、动态字段、错误和 aria 标签。

MVP 必须通过的手动验收：

- 在未配置后端、无密钥时能完成三模块；首次资源加载后断网仍可操作。开发者工具网络记录中没有自动外部请求；主动打开参考文献链接除外。
- 中文→英文→中文往返切换后，消息、token ID、概率、随机数、解题文本与答题状态原样保留；加载另一语言教材明确新开场景。
- 390px/320px、200% 缩放、全键盘与屏幕阅读器检查通过；自动推进可停，来源和结果可读。
- 复跑原六关、四沙盒、训练重置、生成停止、源码查看和刷新恢复，不发生新回归。
- 请至少 5 位目标读者走查三条核心误解；这只是发现设计问题的试用，不作为统计有效的教学提升证明。发现“名字模型在回答中文”或“人工案例是模型实测”的误解即阻止发布并改标记/流程。

第二阶段额外门槛：未确认不发送；发送预览与实际 payload 一致；服务超时/错误/流块拆分/取消可测；服务不暴露 tokenizer 时准确显示 opaque；种子能力声明与实测字段一致；完整执行第 8.3 节协议并可导出重核。验收不要求分步条件优于直接条件，真实的负结果同样合格。

## 10. 分期与首个可交付 MVP

### P0：冻结内容与契约

先确认本方案默认范围；把三个模块的理解题、人工案例、来源标签和数据契约做成可测试 fixture；核对引用与双语术语。产出是审定教材与验收清单，不是新模型选型。若连来源标签都无法清楚区分，先改内容，不先堆动画。

### P1：离线桥接篇（首个可交付 MVP）

按依赖实现 A → B → 能力来源卡和 C → 统一双语/无障碍与回归。新增入口、三模块、独立进度、实际名字模型 runner、判题器与本地结果导出。静态部署仍能完整学习，无外部依赖、遥测或密钥。完成第 9 节全部 MVP 门槛才交付。

MVP 明确尚未交付：真实聊天回答、真实模型的历史消融和求解 A/B、真实聊天 tokenizer 的任意输入可视化、大模型后训练。页面回顾必须说明这一点，不用“完成大模型推理实战”等名称掩盖范围。

### P2：一个后端、两组真实实验

在用户完成数据/部署决策后，只接一个后端；优先由项目维护者配置的本地服务（前提是有设备、许可证和运行能力），否则再明确选择远程代理。完成真实历史条件实验与求解条件对照，不同时扩大题型或堆多模型切换。对模板可见的后端增加实际 tokenizer 层；不透明服务保留限制说明。

可选发布经审核的固定运行记录供离线回放，但回放不是首次实测，也不能代替无模型配置时的真实能力实验。缺少模型 revision 或部署权限时，P1 仍是独立可用的发布版本，P2 不假装完成。

### P3：有学习证据后再扩展

根据试用反馈选择一条：更多验证题型、检索上下文实验、工具调用或持久记忆。每次只新增一个系统机制，并继续区分外部程序结果与模型文本；不把“agent”当作必须完成的产品终点。暂无学习或使用证据时不扩张范围。

## 11. 风险、需决策事项与默认值

| 风险/决策 | 默认处理 | 何时必须重新确认 |
| --- | --- | --- |
| 期待“一打开就是能聊天的大模型” | 产品命名为教学桥接篇；首屏说明名字模型不升级 | 若用户要求首版真实聊天，先明确服务与预算再改范围 |
| 人工案例被当作实测 | 面板级标签、无虚构成本、不得统计能力提升 | 若真实回放替代教材，必须补来源清单及许可 |
| 希望 MVP 使用真实 tokenizer | 默认教学 tokenizer 并明显标记；实现简单、无外部下载 | 若改成真实 tokenizer，先选版本、许可证与本地资源分发方式 |
| 后端运行在哪里 | P1 无后端；P2 优先评估维护者自管本地服务，不自动安装/下载 | 外部服务、模型下载、硬件资源或新增常驻服务都需明确配置 |
| 学习者数据与费用 | 无遥测、仅教材、本地内存；导出需主动操作 | 自定义输入、外发、持久保存和付费批测分别确认政策 |
| 双语实验被错误合并 | UI 双语是必需；教材语言显式切换，评估分层 | 增加新语言时评审任务语义与 tokenizer，不机械翻译实测结果 |
| 后训练内容越做越深 | 一张三步卡＋一个研究案例，链接原文 | 只有用户另要训练课程才实现相关优化实验 |
| 种子/模型版本造成假可复现 | 记录支持性与未知字段；固定离线算法/权重；允许负结果 | 服务版本不可固定时只称可追溯，不称严格复现 |
| 流式输出/XSS/错误泄露 | 原始内容按文本渲染；模型 Markdown 如启用须消毒；错误不带密钥 | 增加 HTML、工具或代码执行时另做安全设计 |
| 主课程被重构拖累 | 独立篇、独立状态；首版不重写整个课程框架 | 多篇课程增长到现结构难维护时再单独评估引擎抽取 |

无需等待的新默认：P1 的路径、模块顺序、三类来源标签、独立进度、中英兼容与不外发内容可直接作为开发依据。必须等待的 P2 决策：运行位置/模型身份、可用硬件、数据条款、费用上限、部署责任人，以及是否允许公开再分发采集记录。没有这些决定，不申请密钥、不发送学习者内容。

## 12. 一手参考资料与使用范围

以下链接已于 2026-10-17 打开核对。论文尽量固定版本；HF 文档为持续更新页面，实施时应再锁定实际使用的库与模型 revision。本方案不采用来源中的产品性能数字作承诺。

- [Hugging Face Transformers — Chat templates](https://huggingface.co/docs/transformers/chat_templating)：消息、模板与 token 的关系，匹配模型格式及特殊 token 注意事项；用于模块 A 与适配器边界。
- [Hugging Face Transformers — How caching works](https://huggingface.co/docs/transformers/cache_explanation)：KV cache 的逐层中间结果复用；用于概念表与模块 B，不据此推导本项目速度。
- [Hugging Face Text Generation Inference — Streaming](https://huggingface.co/docs/text-generation-inference/en/conceptual/streaming)：输出逐步交付与用户可见延迟；用于区分流式 UI 和模型计算，不复制其实现或性能示例。
- [Ouyang 等，2022 — Training language models to follow instructions with human feedback，v1](https://arxiv.org/html/2203.02155v1)：SFT、偏好数据/奖励模型与 PPO 的具体研究路径；不是所有后训练方案的统一定义。
- [DeepSeek-AI，2025 — DeepSeek-R1: Incentivizing Reasoning Capability in LLMs via Reinforcement Learning，v1](https://arxiv.org/html/2501.12948v1)：基础模型上的可验证奖励与多阶段后训练案例；不据其结果保证本篇实验提升。
- [Turpin 等，2023 — Language Models Don't Always Say What They Think: Unfaithful Explanations in Chain-of-Thought Prompting，v2](https://arxiv.org/abs/2305.04388v2)：公开解释的忠实性限制；用于约束“思维链展示”表述，不把个别实验外推到全部模型。

本方案的模块切分、离线默认值、接口、题数与验收门槛是针对当前仓库的设计建议，不是上述文献的结论。
